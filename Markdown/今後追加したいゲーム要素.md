# 『無限ダンジョン』今後追加したいゲーム要素

## この提案の前提

この案は既存の「ゲーム要素まとめ.md」を参照せず、プロジェクト内の C#、ステージ ScriptableObject、Prefab、入力設定、シーンにある実装を見て作成した。コードやアセットが存在することと、現在のプレイで正常に動くことは別なので、実機での動作や最終的な強さは未確認のものとして扱う。

現状の核は、ランダム生成ダンジョンを探索し、左右の手の武器・盾や消耗品で戦い、敵のドロップから装備・素材を得て、攻略値を満たしてポータルで次の階へ進む流れ。敵には徘徊・追跡・捜索のほか、スライムの捕食やハーピーの旋回突進などの個性があり、水場、暗さ、部屋テンプレートが環境の差を作れる。

## 調査で確認した現在の土台

| 領域 | コード・データから確認したこと | 追加案を考える上での意味 |
| --- | --- | --- |
| ダンジョン | `StageData` は自動生成／手作りマップ、部屋ライブラリ、床タイルの重み、敵の出現設定を持つ。部屋Prefabに水場・水路・水没部屋がある。 | 部屋の形だけでなく、目的や環境ルールを変える余地がある。 |
| ステージ進行 | ステージごとに必要攻略値があり、`EnemyHealth` が敵の死亡時に攻略値を加算する。`NextStagePortal` は条件達成後に進行させる。 | 現在の「敵を倒す」以外の進行手段を足すと、探索の選択肢が増える。 |
| 明るさ | `StageData.playerLightRadiusPercent` を `ExplorationManager` がプレイヤー配下の `Light2D` の半径に適用する。確認できた設定例はステージ1が100%、2が87%、3が50%。 | 光を扱う消耗品や報酬は既存のステージ差と直接結び付けられる。 |
| マップ | `MapWindowUI` は訪れた範囲を記録し、壁で遮られた場所を隠すマップを持つ。世代が変わると探索記録を消す。 | 既にあるマップに探索目標・目印・記録報酬を足すのが自然。 |
| 戦闘 | 左右の手、剣攻撃、盾の構え、防具の確率軽減がある。盾は構え中に受けるダメージを軽減する。 | 左右の手を使い分ける戦術や敵の攻撃予告を広げると、既存操作を活かせる。 |
| 敵 | `EnemySpawner` は即時、一度だけ段階出現、継続出現、常時補充のモードを持つ。敵Prefabには水場の速度・ダメージ・回避特性も設定できる。 | 敵を増やすだけでなく、出現方式と地形への反応で難しさを変えられる。 |
| アイテム／クラフト | インベントリは10枠。素材、装備、食材、コイン、瓶などのItemDataがあり、レシピは料理・錬金・精錬・分解などの処理種別を持てる。現状確認できたレシピアセットは8件。 | 所持枠と素材の競合を考慮し、何を持ち帰るか選ぶレシピ設計が合う。 |
| バフ | 回復、毒、速度上昇／低下などの枠組みがあり、アイコン・残り時間を表示するUIがある。ステージ設定で光半径も変わる。 | 新バフは既存枠へ加え、効果の重複・解除・見分け方を決める必要がある。 |

ステージ1の設定例ではマップ幅・高さが各200で、スライムの最大数75、別スライム枠30が常時補充になっている。ステージ2・3も複数の出現枠を持つ。これは設定上の上限であり、実際の同時出現数や負荷、適正難度を示すものではない。敵の種類ごとの個性や攻略値、プレイヤーの攻撃力を合わせてプレイ検証してから数値を調整したい。

## 優先度A：先に遊びの流れを豊かにする

### 1. 敵討伐以外の攻略目標

**現状との接続:** 攻略値は `ExplorationManager` に集約され、敵の死亡から加算される。マップには訪問済み範囲が記録されている。

**提案:** 各階に短い任意目標を1〜3個配置する。例は「封じられた祭壇を調べる」「水路の水門を開く」「部屋にある結晶を回収する」「看板の手掛かりを見つける」。目標を達成すると攻略値、補給、素材のいずれかを得て、敵をすべて狩らなくても出口を目指せるようにする。

**バランスの初期案:** 通常の敵討伐で得る攻略値の合計を基準に、任意目標1個は必要値の15〜25%程度を目安に仮置きする。目標だけで全条件を満たせない構成にし、戦闘・探索のどちらか一方へ偏らないようにする。数値はステージごとの討伐数と所要時間を計測して調整する。

### 2. 部屋ごとの小イベントと発見報酬

**現状との接続:** 部屋ライブラリに複数の形状があり、看板、宝箱、光るクリスタル、水場のPrefabも見つかる。

**提案:** 部屋テンプレートに出現重み付きのイベント種別を追加する。小規模な候補として、封鎖された宝箱、敵の巣、薬草の群生、休憩所、崩落した近道を用意する。部屋に入るだけでなく、危険を処理する／鍵を使う／迂回する選択を置く。

**バランスの初期案:** 通常部屋の大半は現在の戦闘・探索のままにし、報酬付きイベントは1フロアに1〜2部屋程度から試す。回復を置く場合はHP全回復ではなく、消耗品補充か最大HPの一部回復にする。無料回復部屋が続くと死亡時の持ち物損失が意味を失うため、休憩所の頻度と補充量は控えめにする。

### 3. 進行中の撤退・補給判断

**現状との接続:** 死亡時に所持品の一部を落として復帰する処理がある一方、次階へのポータル操作は攻略値達成が条件。インベントリは10枠。

**提案:** ポータルを「次階へ進む」だけでなく「現在階を切り上げる判断点」として見せる。攻略値達成時に、残っている部屋数、未回収の目標、未探索範囲を簡潔に表示する。将来的には、階層間で保持する保管枠や拠点預かりを追加し、探索中の所持品枠と持ち帰りたい素材の判断を作る。

**バランスの初期案:** 先に恒久倉庫を追加すると死亡の緊張感が薄れるため、まずはポータル前の状況表示だけを導入する。保管機能は、死亡時に落とす割合や装備保持ルールと一緒に設計する。

## 優先度B：既存の戦闘・環境を活用する

### 4. 敵の攻撃予告と対処の違い

**現状との接続:** ハーピーには攻撃準備・突進・回復の段階があり、盾には構えがある。敵のAIは種類ごとに異なる。

**提案:** 攻撃直前の予告を、色・姿勢・短い音で読み取れるようにし、攻撃種類ごとに対処を変える。横薙ぎは距離を取る、直線突進は横へ避ける、重い一撃は盾で受けると反撃機会が生まれる、など。盾を使わないと回避できない攻撃は避け、移動でも対応できる逃げ道を残す。

**バランスの初期案:** 予告時間はまず0.6〜1.0秒で試し、敵ごとに見分けがつく差を作る。盾受けの成功報酬は短い隙や位置有利に留め、被ダメージ無効と高威力反撃を同時に与えない。

### 5. 地形と敵・プレイヤーの相互作用

**現状との接続:** `WaterTerrainEffect` は水上で移動速度を変え、敵ごとに水中ダメージや水を避ける設定を持つ。水没ホールや水路の部屋Prefabもある。

**提案:** 水場に加えて、浅瀬／深水、毒沼、崩れる床、暗い部屋などを少数ずつ作る。プレイヤー側には水中速度、環境ダメージの有無を明示し、敵の水耐性・水回避と対比させる。地形の説明は入室時の短い表示か床の視覚表現で伝える。

**バランスの初期案:** 地形ダメージはまず「放置すると危険だが短時間の横断は可能」な水準にする。Prefab設定の水ダメージ値が5の敵もあるため、プレイヤー用の環境ダメージをその値から機械的に流用せず、プレイヤーHP100に対する秒間割合で別途決める。危険地形を必須通路に置く場合は必ず安全な迂回か対策アイテムを用意する。

### 6. 光源・暗視・発光をバフとして拡張

**現状との接続:** ステージごとにプレイヤー光源の半径を変更でき、ステージ3は50%設定。バフ枠とBuff UIが既にある。

**提案:** 光源を広げる発光効果と、視界を補助する暗視効果を追加する。発光は既存のステージ倍率を基準にした相対補正、暗視は一時的な弱い補助光として分ける。暗視だけで壁越しや未探索領域を見通せないよう、マップの遮蔽・発見ルールは維持する。

**バランスの初期案:** 発光は光半径を基準値から15〜25%程度増やす短時間効果、暗視はより短い時間または希少素材の消費にする。ステージ側の倍率とバフ倍率を足し算ではなく乗算にし、極端な暗所でも明るさが無制限に膨らまない上限を設ける。フェード時間はおよそ0.3〜0.8秒を仮置きし、視認性を確認する。

## 優先度C：収集・クラフトに目的を与える

### 7. 食材から完成品までの小さな料理系統

**現状との接続:** 肉、魚、卵、ミルク、塩、小麦粉、蜂蜜、瓶、ボウルなどのアイテムがあり、レシピ形式は料理・錬金・精錬を扱える。確認できたレシピ数は8件。

**提案:** 「生食材→調理品」の短いレシピをまず3〜5個作る。焼き魚は即時回復、スープは短時間の回復バフ、塩漬け肉は弱めだが長持ちするなど、用途とコストを分ける。水場や特定の部屋で材料を見つける意味も持たせる。

**バランスの初期案:** 即時回復量はプレイヤー最大HP100の15〜25%を試験値とし、回復バフは同量の即時回復より合計回復量を低くするか、時間をかけて回復する。強い回復品を安価な共通素材だけで無限に作れる状態は避ける。

### 8. 装備の選択を「強さ以外」でも分ける

**現状との接続:** 片手剣・盾・防具部位に加え、レアリティ、重量、装備見た目、盾の軽減、防具の確率軽減がある。

**提案:** 武器は攻撃速度・射程・硬直、盾は構えやすさ・軽減率、防具は重量と環境耐性など、トレードオフの異なる型を作る。装備の個性は数値を増やすだけでなく、左右の手の組み合わせを変える形にする。例として軽い短剣＋瓶、重い剣＋盾、槍＋小盾を検討する。

**バランスの初期案:** 既存武器を基準に、新装備は平均DPSを大きく上げず、射程・速度・防御中の移動などの強みと弱みを組み合わせる。確率軽減の防具を重ねたときの実効ダメージ軽減も算出し、極端に安全な装備構成を作らない。

### 9. 敵同士の関係を少数の場面で使う

**現状との接続:** 勢力判定やスライムの捕食など、敵がプレイヤー以外へ反応する仕組みの一部がある。

**提案:** 敵対勢力を一度に多数導入せず、「スライムが落ちた食料を食べる」「一部の敵が別勢力を攻撃する」など、既存行動の組み合わせを少数の部屋で見せる。プレイヤーが戦闘を誘導したり、敵が争っている隙に通り抜けたりできるようにする。

**バランスの初期案:** 敵同士の戦闘でプレイヤーの攻略値や報酬を自動的に大量獲得できると、待つだけが最善になりやすい。敵同士で倒した場合の攻略値・ドロップはプレイヤー撃破より控えめにするか、特定イベント以外は報酬対象外にする。

## 優先度D：長期の動機付け

### 10. 階層の節目にボスと準備の機会を置く

**提案:** 数階ごとに固定マップまたは部屋セットを使ったボス階を挟む。ボスは既存の攻撃予告・盾防御・地形を組み合わせ、通常敵のHPを上げただけにはしない。ボス前に補給部屋やクラフト機会を置き、装備の選択が攻略に反映されるようにする。

**バランスの初期案:** 初回は1体の攻撃パターンを少なくし、予告→回避／防御→反撃の繰り返しで学べるようにする。ボス撃破で装備を確定入手させると次階の難度が急上昇しやすいため、素材・選択報酬・次階で使える一時強化を中心に試す。

### 11. 永続セーブとアンロック

**調査上の注意:** 今回の追加調査では、ゲーム進行・インベントリを保存する仕組みがプレイ可能な形で使われているとは確認できなかった。

**提案:** まず「到達した階」「発見した敵・アイテム」「解放した初期装備」など、死亡しても残る軽い記録を設計する。恒久ステータス強化は死亡リスクを急速に無意味にするため、初期アンロックは新しい選択肢や見た目中心にする。セーブを実装するときは、保存データの版管理と破損時の扱いも決める。

## 先に行うとよい検証

新しい要素の数を増やす前に、次の基準プレイを記録すると調整がしやすい。

1. ステージごとの開始からポータル到達までの時間
2. プレイヤーの死亡回数と死亡時に残っていたHP
3. 各階で倒した敵数と攻略値の増分
4. 回復品・素材・装備を拾った数、使った数、インベントリ満杯の回数
5. 敵が同時に画面へ現れた数と、常時補充後の安全な休憩時間
6. 水場や暗い場所で受けたダメージ、迂回・対策の有無

この記録を取れば、例えば必要攻略値200が長すぎるのか、補充型の敵が多すぎるのか、回復品が不足するのかを分けて判断できる。プレイ検証なしにスポーン数や回復量を一律変更するのは避けたい。

## 追加のおすすめ順

1. 敵以外の攻略目標を1種類作り、攻略値への寄与を測る。
2. 既存のマップと部屋ライブラリを使い、任意イベント部屋を1つ試す。
3. 敵の攻撃予告を1体に追加して、盾・回避の両方が成立するか確かめる。
4. 発光または暗視を1種類だけ試作し、ステージ明るさ倍率との合成を確認する。
5. 料理レシピを少数追加し、回復品の消費頻度と10枠インベントリへの圧迫を測る。
6. その後にボス階、永続アンロック、敵勢力イベントへ広げる。

各案の数値は調整開始点であって、確定バランスではない。特にスポーン上限、攻撃力、回復量、階層の所要時間はUnity上でプレイしてから決める。
